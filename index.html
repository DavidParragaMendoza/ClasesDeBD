Bienvenido a la guía técnica de referencia sobre SQL (Structured Query Language) para la materia de Base de Datos 1. Este portal interactivo ha sido desarrollado de forma colaborativa por un equipo de 4 desarrolladores, dividiendo los fundamentos esenciales en módulos especializados con enfoque práctico y minimalista.

💡
¿Qué es SQL?

SQL es el estándar mundial para interactuar con Sistemas Gestores de Bases de Datos Relacionales (RDBMS) como PostgreSQL, MySQL, MariaDB, SQL Server y SQLite. Permite definir la estructura del esquema (DDL), manipular los registros (DML) y consultar información de forma declarativa.

Módulo 1: Creación de Base de Datos y Tablas

Módulo 1 // DDL
DP Responsable Técnico: David Párraga
Módulo Completado

En este módulo aprenderás los comandos de definición de datos (Data Definition Language - DDL) necesarios para dar vida a un nuevo entorno de base de datos desde cero: cómo crear el contenedor principal, seleccionar el esquema de trabajo, comprender los tipos de datos primitivos y construir tablas sólidas con restricciones de integridad.

1. Creación de una Base de Datos (`CREATE DATABASE`)

El primer paso en cualquier arquitectura relacional es declarar el espacio de almacenamiento lógico donde coexistirán todas nuestras tablas, relaciones e índices.

La instrucción fundamental es CREATE DATABASE. Es una excelente práctica incluir la cláusula preventiva IF NOT EXISTS para evitar que el script falle en caso de que la base de datos ya haya sido creada con anterioridad.

SQL • Creación de Base de Datos 
-- 1. Crear la base de datos si no existe previamente
CREATE DATABASE IF NOT EXISTS universidad_db
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- 2. Verificar la creación listando las bases de datos del servidor
SHOW DATABASES;
⭐
Recomendación de Codificación: utf8mb4

Siempre define CHARACTER SET utf8mb4 al crear bases de datos modernas. A diferencia del UTF-8 estándar de 3 bytes de motores antiguos, utf8mb4 soporta soporte completo para 4 bytes, admitiendo acentos, tildes en español, caracteres especiales y emojis sin corrupción de datos.

2. Selección del Esquema Activo (`USE`)

Un servidor de base de datos puede hospedar decenas de bases de datos simultáneamente. Para indicarle al motor SQL sobre cuál de ellas ejecutaremos las sentencias posteriores, usamos el comando USE:

SQL • Selección de Contexto 
-- Establecer universidad_db como la base de datos activa
USE universidad_db;

3. Tipos de Datos Primitivos Esenciales

Antes de declarar una tabla, debemos definir qué tipo de valor almacenará cada columna. El uso correcto de los tipos de datos garantiza integridad y eficiencia de almacenamiento.

Tipo de Dato Descripción Rango / Tamaño Ejemplo de Uso
INT Número entero de 4 bytes con o sin signo. -2,147,483,648 a 2,147,483,647 id_estudiante INT, edad INT
VARCHAR(n) Cadena de texto de longitud variable de hasta n caracteres. 1 a 65,535 caracteres nombre VARCHAR(80), email VARCHAR(120)
DECIMAL(p, s) Número de coma fija exacto. p es la precisión total y s la escala decimal. Valores monetarios y notas promedio DECIMAL(4, 2) (ej. 10.00, 09.50)
DATE Almacena únicamente fecha en formato estándar ISO. YYYY-MM-DD fecha_nacimiento DATE (ej. 2003-05-18)
BOOLEAN Valor lógico binario (internamente equivalente a TINYINT(1)). TRUE (1) o FALSE (0) activo BOOLEAN DEFAULT TRUE
TEXT Cadenas de texto extensas para descripciones largas o artículos. Hasta 64 KB biografia TEXT, observaciones TEXT

4. Creación de Tablas y Restricciones (`CREATE TABLE`)

Una tabla organiza la información en columnas (atributos) y filas (registros o tuplas). Mediante las restricciones (constraints) definimos reglas de validación indispensables:

  • PRIMARY KEY: Identificador único irrepetible de cada fila. No permite valores nulos.
  • AUTO_INCREMENT (o IDENTITY): Genera automáticamente un número secuencial creciente por cada nueva fila insertada.
  • NOT NULL: Exige que el campo obligatoriamente contenga un valor al insertar o modificar.
  • UNIQUE: Garantiza que no existan dos filas con el mismo valor en dicha columna (ideal para correos, cédulas o códigos de matrícula).
  • DEFAULT: Asigna un valor predeterminado si no se especifica uno en el momento del `INSERT`.
SQL • Creación de Tablas con Llaves 
-- 1. Crear tabla padre: carreras
CREATE TABLE IF NOT EXISTS carreras (
  id_carrera INT AUTO_INCREMENT,
  codigo VARCHAR(10) NOT NULL UNIQUE,
  nombre VARCHAR(100) NOT NULL,
  duracion_semestres INT DEFAULT 8,
  PRIMARY KEY (id_carrera)
);

-- 2. Crear tabla hija: estudiantes con llave foránea
CREATE TABLE IF NOT EXISTS estudiantes (
  id_estudiante INT AUTO_INCREMENT,
  matricula VARCHAR(20) NOT NULL UNIQUE,
  nombre VARCHAR(60) NOT NULL,
  apellido VARCHAR(60) NOT NULL,
  email VARCHAR(120) NOT NULL UNIQUE,
  fecha_nacimiento DATE,
  promedio DECIMAL(4, 2) DEFAULT 0.00,
  id_carrera INT NOT NULL,
  activo BOOLEAN DEFAULT TRUE,
  PRIMARY KEY (id_estudiante),
  FOREIGN KEY (id_carrera) REFERENCES carreras(id_carrera)
);

Estructura del Esquema Resultante (`estudiantes`)

5. Comandos de Inspección y Verificación

Una vez ejecutado el script, puedes inspeccionar la estructura de tus tablas mediante comandos nativos:

SQL • Inspección de Esquema 
-- Listar todas las tablas existentes en la base de datos actual
SHOW TABLES;

-- Ver el detalle de campos, tipos y restricciones de una tabla
DESCRIBE estudiantes;

-- Ver la sentencia DDL exacta con la que fue construida la tabla
SHOW CREATE TABLE estudiantes;
⚠️
Peligro Crítico: Comandos Destructivos DDL

El comando DROP TABLE nombre_tabla; o DROP DATABASE nombre_db; elimina instantáneamente la estructura y todos los datos almacenados de forma irreversible sin pedir confirmación. Utilízalos con extrema precaución y nunca en entornos de producción sin un respaldo previo.

Módulo 2: Inserción de Datos en SQL (INSERT INTO)

Módulo 2 // DML
JI Responsable Técnico: Javier Infante
Módulo Completado

Una vez definidas las estructuras y reglas de integridad con los comandos DDL vistos en el Módulo 1, el siguiente paso fundamental es poblar la base de datos con registros reales (también denominados tuplas o filas). En SQL, la instrucción por excelencia para esta tarea es INSERT INTO, perteneciente al subconjunto DML (Data Manipulation Language).

1. Sintaxis Fundamental y Estructura de `INSERT INTO`

La instrucción INSERT INTO le indica al motor relacional en qué tabla debe almacenar nueva información y qué valores asignar a cada una de sus columnas.

En sistemas relacionales con integridad referencial, debemos respetar el orden de dependencia: primero poblamos las tablas maestras o independientes (como carreras) y posteriormente las tablas secundarias o dependientes (como estudiantes), asegurando que las llaves foráneas apunten a filas que verdaderamente existan.

SQL • Poblar Tabla Padre (carreras) 
-- 1. Insertar la primera carrera universitaria
INSERT INTO carreras (codigo, nombre, duracion_semestres)
VALUES ('SIS-01', 'Ingeniería en Sistemas Computacionales', 9);

-- 2. Insertar una segunda carrera
INSERT INTO carreras (codigo, nombre, duracion_semestres)
VALUES ('TEL-02', 'Ingeniería en Telecomunicaciones', 8);

-- 3. Insertar una tercera carrera
INSERT INTO carreras (codigo, nombre, duracion_semestres)
VALUES ('CIV-03', 'Ingeniería Civil', 10);
💡
Concepto Clave: Omisión de Llave Primaria AUTO_INCREMENT

Observa que en la sentencia anterior no mencionamos la columna id_carrera. Dado que fue declarada como INT AUTO_INCREMENT PRIMARY KEY en el Módulo 1, el motor SQL se encarga automáticamente de asignarle de forma correlativa el valor 1, 2, 3, etc., garantizando que jamás se duplique.

2. Inserción con Lista de Columnas vs Inserción Posicional

Existen dos maneras sintácticas de ejecutar un INSERT INTO. Aunque ambas son válidas según el estándar SQL, en entornos profesionales y de producción existe una diferencia crítica de estabilidad:

Enfoque Sintaxis Ventajas Riesgo / Desventajas
Forma Explícita
Recomendada		 INSERT INTO tabla (col1, col2) VALUES (v1, v2); Inmune a cambios futuros en la tabla; orden independiente; permite omitir campos con DEFAULT o NULL. Escribir sentencias ligeramente más largas.
Forma Posicional
No Recomendada		 INSERT INTO tabla VALUES (v1, v2, v3, ...); Menos caracteres al escribir manualmente en consola. Extremadamente frágil: Si se añade una columna con ALTER TABLE, todas las consultas se rompen al instante.
SQL • Buenas Prácticas de Inserción 
-- ✅ FORMA CORRECTA Y ROBUSTA: Especificando las columnas deseadas
INSERT INTO carreras (codigo, nombre, duracion_semestres)
VALUES ('IND-04', 'Ingeniería Industrial', 9);

-- ❌ FORMA FRÁGIL (EVITAR EN CÓDIGO DE PRODUCCIÓN):
-- Requiere conocer la posición física exacta de todas las columnas (incluso el ID NULL)
INSERT INTO carreras
VALUES (NULL, 'IND-04', 'Ingeniería Industrial', 9);
⭐
Regla de Oro de Javier Infante

Declara siempre la lista explícita de columnas en tus consultas de inserción. Si en el futuro otro compañero o una migración añade una columna como fecha_creacion TIMESTAMP, los inserts que no especifiquen columnas fallarán arrojando el clásico Error 1136: Column count doesn't match value count.

3. Inserción de Registros en la Tabla `estudiantes`

Al insertar en tablas con tipos de datos variados, debemos respetar rigurosamente el formato de los literales en SQL:

  • Cadenas y Textos (VARCHAR, TEXT): Se delimitan obligatoriamente con comillas simples (ej. 'Javier', '2026-001').
  • Fechas (DATE): Siguen el estándar internacional ISO-8601 en formato 'AAAA-MM-DD' entre comillas simples (ej. '2003-11-14').
  • Números Enteros y Decimales (INT, DECIMAL): Se escriben sin comillas; los decimales utilizan punto y no coma (ej. 9.45, 1).
  • Valores Booleanos (BOOLEAN): Pueden expresarse como palabras clave TRUE / FALSE o literales numéricos 1 / 0.
SQL • Inserción con Tipos de Datos Mixtos 
-- Inserción de un estudiante asignado a la carrera con id_carrera = 1
INSERT INTO estudiantes (
  matricula,
  nombre,
  apellido,
  email,
  fecha_nacimiento,
  promedio,
  id_carrera,
  activo
) VALUES (
  '2026-001',
  'Javier',
  'Infante',
  'javier.infante@universidad.edu',
  '2003-11-14',
  9.45,
  1,
  TRUE
);

4. Inserción Masiva o por Lotes (Bulk Insert)

Cuando requerimos registrar cientos o miles de registros simultáneamente (por ejemplo, al importar un archivo CSV o migrar datos de un sistema previo), ejecutar un INSERT INTO individual por cada registro resulta ineficiente, ya que el motor debe abrir transacciones de red, verificar bloqueos y escribir en el disco por cada fila.

SQL permite la inserción por lotes (Multi-row Insert) encadenando múltiples grupos de valores entre paréntesis separados por comas dentro de una única instrucción:

SQL • Inserción Masiva Multi-Fila 
-- Inserción simultánea de 3 integrantes del equipo en una sola sentencia atómica
INSERT INTO estudiantes (
  matricula, nombre, apellido, email, fecha_nacimiento, promedio, id_carrera
)
VALUES
  ('2026-002', 'Carlos', 'Bernabe', 'carlos.bernabe@universidad.edu', '2002-08-20', 8.90, 1),
  ('2026-003', 'Deivy', 'Prudente', 'deivy.prudente@universidad.edu', '2003-04-05', 9.15, 1),
  ('2026-004', 'David', 'Párraga', 'david.parraga@universidad.edu', '2001-12-30', 9.80, 1);
⚡
Rendimiento Técnico: Hasta 10x Más Rápido

Un único comando INSERT con 1,000 tuplas se procesa hasta 10 veces más rápido que 1,000 sentencias INSERT individuales, debido a la reducción drástica en la sobrecarga de paquetes TCP/IP y la consolidación de sincronizaciones de log transaccional (Write-Ahead Logging).

5. Comportamiento con AUTO_INCREMENT, DEFAULT y NULL

¿Qué sucede exactamente con una columna cuando decidimos omitirla de la lista de campos en nuestro INSERT INTO? El motor SQL evalúa las restricciones configuradas en la definición de la tabla:

Tipo de Regla Declaración en CREATE TABLE Resultado al Omitir en INSERT
Secuencia Automática AUTO_INCREMENT PRIMARY KEY Calcula el valor máximo actual + 1 y lo asigna sin error.
Valor Predeterminado DEFAULT valor (ej. DEFAULT 0.00) Inyecta automáticamente el valor por defecto configurado.
Admite Nulos Sin restricción NOT NULL Almacena el valor especial NULL (ausencia de dato).
Obligatorio Estricto NOT NULL sin cláusula DEFAULT RECHAZA LA CONSULTA: Devuelve un error y cancela la inserción.
SQL • Inserción Apalancada en Valores por Defecto 
-- Solo enviamos columnas obligatorias sin default:
-- id_estudiante tomará el siguiente correlativo (5)
-- promedio tomará automáticamente 0.00 (DEFAULT)
-- activo tomará automáticamente TRUE (DEFAULT)
-- fecha_nacimiento tomará NULL
INSERT INTO estudiantes (matricula, nombre, apellido, email, id_carrera)
VALUES ('2026-005', 'Mariana', 'López', 'mariana.lopez@universidad.edu', 1);

6. Diagnóstico de Errores Comunes en Tiempo de Inserción

Al manipular datos relacionales, el motor SQL actúa como un centinela estricto. A continuación se presentan los errores más habituales que todo desarrollador debe dominar y cómo solventarlos:

Código de Error Mensaje Típico del Motor SQL Causa Raíz Solución Práctica
Error 1062 Duplicate entry '...' for key 'email' Se intentó insertar un valor repetido en una columna restringida con UNIQUE o PRIMARY KEY. Verificar con un SELECT previo o usar identificadores únicos válidos.
Error 1452 Cannot add child row: foreign key constraint fails Se especificó un id_carrera que no existe en la tabla padre referenciada. Insertar primero el registro en la tabla padre (carreras) antes de asociarlo.
Error 1136 Column count doesn't match value count at row 1 La cantidad de columnas listadas no coincide exactamente con la cantidad de valores pasados en VALUES. Contar y emparejar cada columna declarada con su respectivo valor.
Error 1364 Field 'nombre' doesn't have a default value Se omitió una columna NOT NULL que no posee valor predeterminado. Incluir obligatoriamente la columna en la lista o asignarle un valor DEFAULT en el DDL.
Error 1265 Data truncated for column 'promedio' El valor sobrepasa la longitud de un VARCHAR(n) o la escala permitida de un DECIMAL. Ajustar el valor numérico al formato definido (ej. 9.75 para DECIMAL(4,2)).
⚠️
Atención: La Integridad Referencial es Inquebrantable

Si intentas insertar un estudiante con id_carrera = 99 cuando en la tabla carreras solo existen los identificadores 1, 2 y 3, el motor abortará la transacción para proteger la consistencia de la base de datos. ¡Nunca desactives las llaves foráneas para "forzar" inserciones de datos huérfanos!

Módulo 3: Consultas de Selección (SELECT, WHERE, LIKE)

Módulo 3 // DQL
CB Responsable Técnico: Carlos Bernabe
Módulo Completado

Una vez creada la base de datos y poblada con información, la operación más frecuente en el ciclo de vida de cualquier sistema informático es la recuperación y análisis de datos. En SQL, estas operaciones pertenecen al DQL (Data Query Language) y se fundamentan en la instrucción SELECT, el equivalente computacional de los operadores de Proyección ($\pi$) y Selección ($\sigma$) del álgebra relacional.

1. La Sentencia `SELECT` y Proyección de Columnas

La proyección nos permite especificar exactamente qué atributos o columnas deseamos recibir como resultado de una consulta.

Existen dos formas fundamentales de proyección:

  • Proyección Total (SELECT *): Solicita todas las columnas físicas de la tabla en el orden en que fueron declaradas en el DDL.
  • Proyección Específica (SELECT col1, col2): Solicita únicamente los atributos necesarios para la vista o pantalla del usuario.
SQL • Proyecciones con SELECT 
-- 1. Proyección total: Obtener todas las columnas de la tabla carreras
SELECT * FROM carreras;

-- 2. Proyección específica: Solo nombres y correos de los estudiantes
SELECT nombre, apellido, email
FROM estudiantes;

-- 3. Uso de Alias (AS) para renombrar columnas en el resultado y expresiones
SELECT 
  matricula AS Carnet_Estudiante,
  CONCAT(nombre, ' ', apellido) AS Nombre_Completo,
  promedio AS Calificacion_General
FROM estudiantes;
⭐
Regla de Rendimiento de Carlos Bernabe: Evita SELECT * en Producción

Aunque SELECT * es muy cómodo al interactuar con la consola interactiva, en aplicaciones web comerciales debes evitarlo. Traer columnas innecesarias satura el ancho de banda de red, impide el uso de Covering Indexes en el motor de base de datos y consume memoria innecesaria en el servidor web. Proyecta siempre de forma explícita solo los atributos que tu interfaz va a renderizar.

2. Filtrado Condicional con la Cláusula `WHERE`

Sin un mecanismo de filtro, las consultas retornarían millones de filas indiscriminadamente. La cláusula WHERE actúa como un predicado lógico que evalúa cada registro: solo aquellas filas donde la condición resulte en TRUE formarán parte del conjunto resultante.

Operador Tipo Significado / Acción Ejemplo de Consulta SQL
=, != (o <>) Comparación Igualdad y desigualdad estricta. WHERE activo = TRUE, WHERE id_carrera != 2
>, <, >=, <= Relacional Comparaciones numéricas, de texto o fechas. WHERE promedio >= 9.00, WHERE fecha_nacimiento < '2004-01-01'
AND Lógico Intersección: Ambas condiciones deben cumplirse. WHERE id_carrera = 1 AND promedio >= 8.5
OR Lógico Unión: Basta con que al menos una condición sea verdadera. WHERE id_carrera = 1 OR id_carrera = 3
BETWEEN ... AND ... Rango Verifica inclusión dentro de un rango cerrado [a, b]. WHERE promedio BETWEEN 8.00 AND 10.00
IN (...) Pertenencia Comprueba si el valor coincide con cualquier elemento de una lista. WHERE id_carrera IN (1, 2, 4)
IS NULL / IS NOT NULL Nulidad Evalúa la presencia o ausencia de valor (Lógica trivalente). WHERE fecha_nacimiento IS NOT NULL
SQL • Consultas Condicionales Complejas 
-- 1. Alumnos de excelencia: Carrera 1 con promedio mayor o igual a 9.0
SELECT matricula, nombre, apellido, promedio
FROM estudiantes
WHERE id_carrera = 1 AND promedio >= 9.00;

-- 2. Alumnos con promedio intermedio usando BETWEEN
SELECT nombre, apellido, promedio
FROM estudiantes
WHERE promedio BETWEEN 8.00 AND 9.50;

-- 3. Uso de IN para filtrar múltiples carreras sin encadenar muchos OR
SELECT matricula, nombre, id_carrera
FROM estudiantes
WHERE id_carrera IN (1, 3);
💡
Lógica Trivalente en SQL: ¿Por qué campo = NULL nunca funciona?

En SQL, el valor NULL no representa el valor cero ni una cadena vacía, sino un estado de desconocimiento. En la lógica trivalente de SQL (TRUE, FALSE, UNKNOWN), comparar cualquier cosa con NULL mediante el operador = devuelve siempre UNKNOWN, haciendo que la fila sea descartada. Por esta razón, la sintaxis obligatoria es siempre columna IS NULL o columna IS NOT NULL.

3. Búsqueda de Patrones de Texto con la Cláusula `LIKE`

Cuando no conocemos el valor exacto de un texto (por ejemplo, buscar un usuario por su inicial, filtrar correos de un dominio específico o buscar por apellido), utilizamos el operador LIKE acompañado de caracteres comodín (wildcards):

  • % (Signo de Porcentaje): Representa cero, uno o múltiples caracteres cualesquiera.
  • _ (Guión Bajo): Representa exactamente un único carácter en esa posición fija.
Patrón de Búsqueda Interpretación Valores que Coinciden Valores que NO Coinciden
LIKE 'Carlos%' Inicia con "Carlos", seguido de cualquier cantidad de texto. "Carlos", "Carlos Bernabe", "Carlos Alberto" "Juan Carlos", "carlos" (en motores sensibles)
LIKE '%@universidad.edu' Termina con el dominio institucional especificado. "carlos@universidad.edu", "david@universidad.edu" "carlos@gmail.com", "universidad.edu.ec"
LIKE '%Sistemas%' Contiene la subcadena en cualquier posición del texto. "Ingeniería en Sistemas", "Sistemas Distribuidos" "Ingeniería Civil", "Industrial"
LIKE 'SIS-__' Inicia con "SIS-" seguido de exactamente dos caracteres. "SIS-01", "SIS-02", "SIS-99" "SIS-1", "SIS-001", "SIS"
LIKE '_a%' El segundo carácter debe ser obligatoriamente la letra 'a'. "Carlos", "David", "Javier" "Deivy", "Bruno", "Ana"
SQL • Búsquedas Avanzadas con LIKE 
-- 1. Filtrar estudiantes cuyo correo pertenezca al dominio institucional
SELECT matricula, nombre, apellido, email
FROM estudiantes
WHERE email LIKE '%@universidad.edu';

-- 2. Buscar matrículas registradas en el año 2026
SELECT matricula, nombre, apellido
FROM estudiantes
WHERE matricula LIKE '2026-%';

-- 3. Búsqueda combinada: Nombre que empiece con 'D' y promedio sobresaliente
SELECT matricula, nombre, apellido, promedio
FROM estudiantes
WHERE nombre LIKE 'D%' AND promedio >= 9.00;

4. Ordenamiento de Resultados (`ORDER BY`) y Paginación (`LIMIT`)

En SQL, las filas de una tabla no tienen un orden físico garantizado. Si requerimos los datos ordenados alfabéticamente o por rendimiento académico, debemos especificar ORDER BY junto a ASC (ascendente) o DESC (descendente).

SQL • Ordenamiento y Paginación 
-- Top 3 estudiantes con los mejores promedios de la carrera de Sistemas (id 1)
SELECT matricula, nombre, apellido, promedio
FROM estudiantes
WHERE id_carrera = 1
ORDER BY promedio DESC
LIMIT 3;

Módulo 4: Actualización y Borrado de Datos (UPDATE y DELETE)

Módulo 4 // DML
DP Responsable Técnico: Deivy Prudente
Módulo Completado

Los sistemas dinámicos no son estáticos: los alumnos cambian de promedio, actualizan su correo de contacto o eventualmente egresan y son dados de baja. En este módulo, cubriremos las dos sentencias modificadoras de tuplas: UPDATE para editar datos existentes y DELETE para eliminar registros de una tabla, abordando con especial detalle las normas de seguridad críticas para evitar desastres en producción.

1. Actualización de Datos con `UPDATE`

La instrucción UPDATE modifica el valor de una o más columnas en una tabla sobre las filas que coincidan con la condición especificada en el WHERE.

Estructura general:

UPDATE nombre_tabla
SET columna1 = nuevo_valor1, columna2 = nuevo_valor2
WHERE condicion_especifica;
SQL • Ejemplos de Modificación Segura 
-- 1. Actualizar el promedio de un estudiante específico por su ID único
UPDATE estudiantes
SET promedio = 9.90
WHERE id_estudiante = 1;

-- 2. Actualizar múltiples columnas simultáneamente (correo y estado activo)
UPDATE estudiantes
SET 
  email = 'deivy.prudente@universidad.edu',
  activo = TRUE
WHERE matricula = '2026-004';

-- 3. Actualización computada: bonificar 0.25 puntos a los alumnos de Sistemas
UPDATE estudiantes
SET promedio = promedio + 0.25
WHERE id_carrera = 1 AND promedio <= 9.75;

2. Eliminación de Registros con `DELETE`

La instrucción DELETE FROM elimina permanentemente del almacenamiento una o más tuplas existentes que satisfagan el predicado lógico indicado.

SQL • Eliminación de Filas con DELETE 
-- 1. Eliminación puntual: Borrar un estudiante por su Clave Primaria
DELETE FROM estudiantes
WHERE id_estudiante = 4;

-- 2. Eliminación condicional: Depurar registros inactivos con promedio nulo
DELETE FROM estudiantes
WHERE activo = FALSE AND promedio = 0.00;
🚨
¡ALERTA MÁXIMA DE DEIVY PRUDENTE: NUNCA EJECUTES UPDATE O DELETE SIN WHERE!

Si ejecutas UPDATE estudiantes SET promedio = 10.0; sin la cláusula WHERE, el motor modificará todas y cada una de las filas de la tabla sin pedir confirmación.

De forma análoga, si ejecutas DELETE FROM estudiantes; sin WHERE, ¡vaciarás por completo la tabla perdiendo toda la información del alumnado!

🛡️ Protección recomendada: Activa el modo seguro en tu cliente SQL ejecutando: SET SQL_SAFE_UPDATES = 1;. Este parámetro bloquea automáticamente cualquier comando que no utilice una llave primaria o índice en el WHERE.

3. Comparativa Definitiva: `DELETE` vs `TRUNCATE` vs `DROP`

En entrevistas de trabajo y exámenes de Base de Datos 1, la distinción entre estas tres operaciones de supresión de datos es una de las preguntas técnicas más recurrentes:

Criterio Técnico DELETE TRUNCATE TABLE DROP TABLE
Categoría SQL DML (Manipulación de Datos) DDL (Definición de Datos) DDL (Definición de Datos)
¿Permite WHERE? SÍ (Filtrado selectivo) NO (Vacía toda la tabla) NO (Destruye toda la tabla)
¿Conserva la Estructura? Sí, la tabla permanece vacía o parcial. Sí, conserva columnas, índices y tipos. No, borra metadatos, índices y estructura.
Reseteo de AUTO_INCREMENT No resetea el contador correlativo. Sí resetea el contador a 1. Inaplicable (la tabla deja de existir).
Velocidad y Mecanismo Lento (borra fila por fila y escribe logs). Ultra Rápido (desasigna bloques de páginas). Instantáneo a nivel de catálogo.
Transacciones y ROLLBACK Permite deshacer con ROLLBACK. No reversible en la mayoría de motores. No reversible (DDL auto-commit).

4. Integridad Referencial ante Borrados (`FOREIGN KEY`)

¿Qué ocurre si intentamos eliminar la carrera con id_carrera = 1 (Sistemas) cuando existen estudiantes vinculados a ella? El motor relacional reaccionará de acuerdo a la cláusula declarada en la llave foránea:

  • ON DELETE RESTRICT (o NO ACTION): Es la regla por defecto. El motor rechaza el borrado arrojando Error 1451: Cannot delete or update a parent row: a foreign key constraint fails.
  • ON DELETE CASCADE: Al eliminar la carrera padre, elimina en cascada automáticamente a todos los estudiantes inscritos en ella.
  • ON DELETE SET NULL: Conserva a los estudiantes, pero asigna el valor NULL en su columna id_carrera.
⭐
Uso Prudente de ON DELETE CASCADE

Ten sumo cuidado con CASCADE en tablas centrales de tu negocio. Si borras un cliente y la base de datos tiene configurado borrado en cascada sobre ventas y facturas, podrías eliminar involuntariamente todo el historial contable de tu organización.

5. Buenas Prácticas: Transacciones Seguras (`START TRANSACTION`)

Para protegerte contra modificaciones accidentales al trabajar en entornos reales, utiliza el patrón de transacciones manuales:

SQL • Patrón de Modificación Segura con Transacciones 
-- 1. Iniciar un bloque transaccional atómico
START TRANSACTION;

-- 2. Ejecutar la actualización o eliminación
UPDATE estudiantes
SET activo = FALSE
WHERE matricula = '2026-001';

-- 3. Inspeccionar el efecto antes de consolidar
SELECT id_estudiante, matricula, nombre, activo
FROM estudiantes
WHERE matricula = '2026-001';

-- 4A. Si el resultado es correcto, confirmar definitivamente:
COMMIT;

-- 4B. Si hubo un error o modificó más filas de las esperadas, deshacer todo:
-- ROLLBACK;
